# PAIOS · Development Workflow

文档版本：1.0.0 | 架构目标：V1.1 | 状态：Proposed

更新时间：2026-11-11（Asia/Shanghai）

## 目的与输入

以小范围、可验证和可追溯的改动完成开发任务。输入包括问题描述、预期行为、验收条件、代码位置、允许变更的范围、已知约束和恢复方式。

## 执行步骤

1. **检查实际环境**：确认路径、仓库、已有变更、运行入口和相关说明；不把 Vault 或父文件夹自动当成代码仓库。
2. **明确方案**：读取 [Global](../AI_Instructions/Global.md)、[开发指令](../AI_Instructions/Development.md) 和 [ADR-003](../Decisions/ADR-003-Model-Agnostic-Harness.md)。小改动直接说明方案；涉及核心架构、存储或新依赖的变更先写 Proposed ADR。
3. **最小实现**：只修改任务范围内内容，保护未提交工作和已有笔记。模型与 Harness 配置通过可替换边界接入，不把知识资产绑进供应商格式。
4. **验证结果**：先定义成功和失败的观察方式，再运行适合改动的检查；涉及行为变化时检查正常路径、关键边界和失败路径。只改文档时检查可读性、链接和内容一致性即可。
5. **记录真实状态**：记下运行方式、必要环境信息、预期与实际结果、未运行的检查；失败则定位或说明阻塞，不伪造成功。
6. **交付与版本记录**：在 `03_Projects/` 新建或经授权更新项目笔记，沿用[既有项目模板](../../03_Projects/模板%20C：项目笔记.md)；记录代码仓库位置、文件变化、验证证据和恢复办法。提交时核对具体文件及差异。
7. **复盘**：记录重复故障或执行摩擦，必要时进入 [Evolution](Evolution.md)。

## 输出与完成条件

产物、验证记录、限制、下一步与恢复路径齐全；关键验收满足才标记完成。项目文档使用 Markdown，代码及测试按项目实际语言维护，不要求把可执行文件改成 Markdown。

当前没有检查 DeepSeek Harness 的源代码、模型切换能力或运行入口；首次使用时需按实际环境确认，不把本流程视为已完成集成。
