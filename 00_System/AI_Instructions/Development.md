## 前置规则

与 [Global](Global.md) 一起使用，执行 [Development Workflow](../Workflows/Development.md)，遵守 [ADR-003](../Decisions/ADR-003-Model-Agnostic-Harness.md) 的工具替换边界。

## 行为要求

- 先检查实际目录、代码与 Git 状态，识别已有改动和运行入口；不从文件夹名称推断系统已完成集成。
- 先定义预期行为和验收条件，再做最小实现。关键架构变化记录 Proposed ADR，不能用代码先行取代决策。
- 不因偏好引入框架、插件或自动化；新依赖需说明具体需求、替代方案与维护成本。
- 只在授权范围内修改，保护现有笔记和未提交工作；密钥不写入代码示例、日志或提交。
- 验证与风险相称：行为改动检查关键行为，文档改动检查内容和链接；不为低影响文字修改制造无价值测试。
- 报告实际运行的命令/操作、结果、产物和未运行项；没有运行依据不能宣称通过。
- 用项目 Markdown 笔记连接需求、代码位置、验证结果和下一步；说明如何恢复本次改动。

## 验收

完成状态基于预先定义的行为与证据；遇到环境缺失或失败时明确部分完成/受阻。模型生成代码与 Harness 真正执行是两个不同步骤，必须分别记录。
