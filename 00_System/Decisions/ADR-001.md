# ADR-001: Knowledge Architecture · 知识架构

文档版本：1.0.0 | 架构目标：V1.1

更新时间：2026-11-11（Asia/Shanghai）

## Status

**Accepted**。决策人：PAIOS 负责人（用户）；本次补录日期：2026-11-11。依据：用户说明及本地 Vault。原始选型日期未知；这是对当前选择的补录，不伪造历史批准时间。

验证状态：本地 Markdown 和目录存在已确认；长期效果、跨设备恢复与替换编辑器的实际演练尚未验证。

## Context

PAIOS 需要长期保存研究、学习与项目成果，并在替换 AI 平台时保留知识及设计理由。现有 `My AI Brain` 使用 Obsidian 目录和 Markdown 模板，用户要求保留现有笔记。

## Decision

使用 **Markdown 作为持久知识格式，Obsidian 作为当前核心知识管理工具**。系统规范独立放在 `00_System/`，使用 Git 管理版本；普通业务成果按实际目录存放。

Obsidian 可更换，Markdown 资产与语义应保留。首次 Git 纳入范围为系统规范，业务笔记的后续跟踪及备份策略待定，见 [VERSIONING](../VERSIONING.md)。

## Alternatives

| 方案 | 选择时考虑的取舍 |
| --- | --- |
| Obsidian + Markdown | 与当前环境一致，正文可直接在本地编辑，适合知识链接和文本历史管理 |
| Notion | 可以作为另一种工作空间；本项目优先考虑本地正文与工具可替换性，未开展同条件对照实验 |
| Logseq | 可作为另一种知识组织方式；是否适合个人习惯尚未评估 |
| 仅 Markdown 编辑器 | 可作为轻量替代；组织与浏览体验需自行验证 |

此比较是本项目取舍，不宣称其他产品无法导出、离线或进行任何特定操作。

## Reasons

本地文件优先、Markdown 可移植、文本适合 Git 版本管理、知识链接可保留上下文，并避免依赖单一 AI 平台。上述是选择理由，不是已测得的效率提升。

## Consequences

**Positive（预期）**：资产可控，可由不同编辑器和 AI 读取；设计理由能随文件迁移。

**Negative**：需要自行维护整理流程、链接和备份；编辑器专有语法与插件可能降低迁移性；多设备同步尚待设计。Git 本地提交不能代替独立备份。

恢复/替换：先用其他编辑器打开副本并检查链接和关键内容，再决定迁移；保留原文件及历史，不先删除 Vault。

## Review Trigger

知识规模、协作、跨设备需求或自动化需求显著变化；链接维护成本过高；替换编辑器演练失败。
