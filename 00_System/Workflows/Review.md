# PAIOS · Review Workflow

文档版本：1.0.0 | 架构目标：V1.1 | 状态：Proposed（步骤与记录格式）

更新时间：2026-11-11（Asia/Shanghai） | 周/月节奏：用户已指定

## 每周：检查体验与小改进

1. 查看本周真实任务、成果路径和未完成项，采集 [EVALUATION](../EVALUATION.md) 的适用指标。
2. 记录最明显的摩擦及具体实例：发生在哪一步、几次、造成什么影响；没发生问题就如实记录。
3. 检查待处理成果和重复劳动，区分任务本身困难与系统流程缺陷。
4. 最多选一个主要瓶颈进入 [Evolution](Evolution.md)，先形成假设及验收条件，不立即安装工具。
5. 新建 `06_Reviews/日期-Weekly-Review.md`；重名时先检查，保留历史。

## 每月：评估架构与决策

1. 汇总周复盘、实验结果和维护成本；不足一个月也可做初次检查，但不宣称月度趋势。
2. 逐条检查 ADR 的 Review Trigger 是否出现，检查工具副本是否落后于规范。
3. 审视层级职责、知识沉淀、可移植性和未决问题；检查是否存在两份互相冲突的规范。
4. 对改进作出接受、继续试验或拒绝的判断；重大决策落 ADR，失败结果也保留。
5. 只有满足 [VERSIONING](../VERSIONING.md) 才发布；否则记录“本月不发布”及原因。
6. 新建 `06_Reviews/日期-Monthly-Review.md`，链接实验、ADR 和下一轮行动。

## 最小复盘格式

```markdown
# PAIOS 周复盘 / 月复盘
文档版本：1.0.0
更新时间：YYYY-MM-DD（Asia/Shanghai）
覆盖期间：
所用规范版本：
## 本期任务与成果
## 指标、原始证据与缺失数据
## 观察到的问题及影响
## 根因假设与替代解释
## 实验 / ADR / 标准化决定
## 下一步、负责人及检查时间
## 发布结论与理由
```

此文件定义人工节奏，不创建提醒或定时任务。复盘文档放 `06_Reviews/`，系统实验放 `00_System/Experiments/`，正式规则回到 `00_System/` 对应文件。
