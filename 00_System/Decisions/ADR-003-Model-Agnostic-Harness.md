# ADR-003: Model-Agnostic Harness · 模型无关的执行架构

文档版本：1.0.0 | 架构目标：V1.1

更新时间：2026-11-11（Asia/Shanghai）

## Status

**Accepted（架构方向及当前工具选择）**。决策人：PAIOS 负责人（用户）；记录日期：2026-11-11，依据本次明确要求。

验证状态：用户及既有笔记报告当前使用 DeepSeek Harness；本次未检查其实现、配置或运行结果。通用任务协议和模型切换能力均为 **Proposed / 待验证**，不宣称已有通用适配层。

## Context

PAIOS 需要把智能推理与实际文件、代码执行区分开。若系统规范、任务语义和知识资产完全依赖某个模型或执行器，更换工具会造成重建成本。

## Decision

采用模型无关的 Harness 设计方向：模型负责推理与方案，Harness 负责在已授权范围内协调执行、工具调用和结果记录。当前以 DeepSeek Harness 作为用户选择的执行环境；不据此规定所有未来任务必须使用 DeepSeek。

任务目标、规范、验收标准和最终成果采用工具之外也能理解的表达。模型专有配置留在执行工具侧。[ARCHITECTURE](../ARCHITECTURE.md) 的最小 Markdown 交接协议是候选接口，先试用，不立即新建抽象框架。

## Alternatives

| 方案 | 取舍 |
| --- | --- |
| 与单一模型深度绑定 | 初期可能简单，但替换成本与供应商依赖需承担 |
| 模型无关的任务边界 + 当前 Harness | 保留当前环境，逐步验证可移植性；本次选择 |
| 只做对话，全部手工执行 | 仍可作为简单任务或故障时的退路，执行记录需人工维护 |
| 立即建设复杂 Agent 平台 | 当前无必要性证据，不纳入本次建设 |

## Reasons

保持架构、知识和任务语义独立于模型；允许未来比较不同模型或执行器；用结果与验证证据评价执行，而非用品牌名称评价系统成熟度。

## Consequences

**Positive（预期）**：替换模型时可沿用任务规范，运行记录能脱离聊天理解。

**Negative**：不同工具的输入、调用方式和结果格式可能不兼容；需要逐步验证；过早抽象会增加维护成本。

恢复/替换：保留已知可用流程，以同一小任务手工或用另一执行工具复演，比较产物与证据。迁移未通过前不删原配置，不把“模型无关”写成已实现能力。

## Review Trigger

换模型必须重写大量工作流；Harness 无法提供必要执行记录；反复出现权限或失败恢复问题；维护成本超过节省的工作量。
