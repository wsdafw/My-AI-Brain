# PAIOS · Research Workflow

文档版本：1.0.0 | 架构目标：V1.1 | 状态：Proposed

更新时间：2026-11-11（Asia/Shanghai）

## 目的与输入

把研究从聊天转成可追溯、可继续的知识资产。开始时写清研究问题、范围、预期用途、时间预算与验收条件；区分需要外部资料的问题和仅需整理已有资料的问题。

## 执行步骤

1. **读取上下文**：读取 [Global](../AI_Instructions/Global.md)、[研究指令](../AI_Instructions/Research.md)、相关已有笔记和 ADR；声明缺失信息。
2. **制定研究问题**：把主题拆成少量可回答的问题，定义什么证据足够回答，以及哪些内容暂不研究。
3. **获取与核查证据**：记录来源标题、作者或机构、链接、发布日期（可得时）及访问日期；关键技术事实优先核对原始文献或官方资料。无法核实的内容标记待核实。
4. **综合结论**：分开写来源支持的事实、自己的推论、竞争性解释和待验证假设；保留不一致证据。
5. **保存成果**：新建 `01_Research/日期-主题.md`（命名仅为建议），与[既有研究模板](../../01_Research/模板%20A：研究笔记.md)兼容；同名文件存在时先读取，未经授权另存而非覆盖。
6. **完成验收**：实际打开保存的文件，检查来源、未解问题、下一步及链接；记录整理耗时与保存是否在任务结束前完成。没有写入权限时交付完整 Markdown 并标注“待保存”，不能声称已沉淀。
7. **形成反馈**：可复用结论经过核查后再整理至 `04_Knowledge/`；遇到流程问题记入 `06_Reviews/`，必要时进入 [Evolution](Evolution.md)。

## 最小成果协议（Proposed）

继续保留既有模板的八个标题，不修改模板原文件：

| 模板部分 | 新笔记中应补充的内容 |
| --- | --- |
| 研究问题、背景与动机 | 范围、用途、验收条件 |
| 核心理论、相关论文与资料 | 来源、适用条件、访问日期与可核查定位 |
| 关键发现 | 简短回答、事实与推论的区别、对应来源 |
| 未解决的问题、我的假设 | 不确定性、冲突证据、假设的验证方法 |
| 下一步研究计划 | 下一次可执行动作；成果路径、流程版本、验证与整理耗时 |

新笔记须注明标题、文档版本和更新时间；可保留模板已有的 `type`、`status`、`date` 等属性，不把研究状态与治理状态混为一谈。

## 完成条件与试验

问题得到回答或边界明确；关键事实可核查；文件已保存可打开；未解决问题没有被省略。质量与耗时按 [EVALUATION](../EVALUATION.md) 记录。首次通过 [EXP-001](../Experiments/EXP-001-Research-Capture.md) 评估，当前没有实测结果。
